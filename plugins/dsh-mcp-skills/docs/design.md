# 设计说明：MCP 与技能设置页

本文是 `@pcmid/dsh-mcp-skills` 第一版的交互与视觉约定，实现以它为准。调研依据见工作区 `.tools/oc-notes/report.md`（OpenChamber 的 MCP / Skills 设置页）。

## 目标与范围

- 用户不用写配置文件，就能在 DSH 设置里添加、测试、修改、停用、删除 MCP 服务器，并新建、导入、编辑、删除技能。
- 已确认的用户选择：
  - 0.2：技能支持多选删除；导入改为「技能仓库」（添加链接 → 扫描 → 安装），之后可以在仓库里检查和安装更新。
  - 设置导航里放两个独立条目：「MCP 服务器」（order 12）、「技能」（order 13），都排在「模型」之后。
  - 技能页包含：从 GitHub 链接或本地文件夹导入、项目级技能（按工作区）、DSH 内置的只读技能。
  - 技能的存放位置可以选：个人 / 项目 × DSH 专用 / 通用（`.agents`）。默认值取「上次选择」，第一次是「个人 · DSH 专用」（与 OpenChamber 一致：默认个人级、工具专用目录）。
- 不在第一版：OAuth、MCP 按项目启用、技能「完全关闭」、Agent 工具。

## 业务事实（不能改变含义）

- MCP 服务器存在 `mcp-manager` 行的 volatile `servers` 里，通过设置表单 `ctx.configForms.get('mcp-manager')` 读写，写入用路径操作 `form.mutate([{ op: 'set' | 'unset', path: ['servers', name, ...], value }])`。
  - 快照里 `base` 是下层组合配置（bundle 等），`user` 是用户层原样值。名字只在 `base` 里 → 「来自内置配置」；只在 `user` 里 → 用户添加；两边都有 → 用户覆盖了内置配置。删除用户添加的条目 = unset；对内置条目 unset = 恢复默认。
  - `ctx.remote.mcpManager.watch()` 推送的列表里还有插件注册的服务器（不在 base/user 里）：只读，标「插件提供」。
  - 服务器名 `[A-Za-z0-9_-]{1,32}`，同时是工具名前缀 `mcp__<名>__`。
  - 校验规则（与 Host 一致，写入前在前端先校验，字段下方报错）：stdio 必须有 `command`，不能有 `url`/`headers`；streamable-http 必须有 `url`，不能有 `command`/`args`/`env`/`cwd`；`${credential:REF}` 模板语法要合法。
  - 任何字段（`enabled` 除外）变化都会让该服务器重新连接。`enabled: false` 停掉进程但保留条目。
  - 状态：`connecting` / `connected{toolCount, connectedAt}` / `reconnecting{attempt, maxAttempts, nextRetryAtMs, lastError}` / `failed{reason, lastError?}` / `waiting-credentials{lastError}` / `closed` / `disabled`。`restart(name)` 重连并重置重试预算；`probe(name)` 单独连一次，返回工具名（停用的条目也能测）。
- 密钥：环境变量 / 请求头的值标为「密钥」时，值写入 DSH 凭据库（`ctx.remote.credentials.set(ref, value)`），配置里只存 `${credential:REF}`。REF 命名 `MCP_<服务器名>_<键名>`，大写、非字母数字换成 `_`。`describe([refs])` 返回 `{configured, source?, writable}`，用来显示「已保存 / 缺失」。
- 技能：目录 `<root>/<name>/SKILL.md`（也兼容平铺 `<root>/<name>.md`），YAML frontmatter：`name`（kebab-case）、`description`（必填）、可选 `whenToUse`、`disable-model-invocation`、`user-invocable`。
  - 根目录与优先级（数字小的优先）：项目 DSH `<项目>/.dsh/skills`(100) → 项目通用 `<项目>/.agents/skills`(200) → 个人 DSH `~/.dsh/skills`(400) → 个人通用 `~/.agents/skills`(500) → 内置(600)。项目根 = 工作区路径往上最近的含 `.git` 的目录，没有就是工作区路径本身。
  - 同名时优先级高的生效，其余显示「被覆盖」。
  - 改文件后 DSH 自动发现，无需重启。

## 页面结构（两页共用）

设置面板内容列约 560px 宽，放不下 OpenChamber 的「280px 列表 + 编辑器」，两页都用「列表 → 详情」的下钻：

- 列表视图：页面标题（h2，16px/500）+ 一句说明（14px，tertiary）+ 内容。
- 详情视图：顶部一行「‹ 返回」按钮（文字是上级页面名，ghost 小按钮），下面是对象标题 + 状态；底部是操作行。
- 视图状态与未保存的草稿放在插件的 controller store 里，关掉设置再打开还能回到原处、草稿不丢。
- 进入详情时把焦点放到标题；返回列表时焦点回到刚才打开的那张卡片 / 那一行。

## MCP 服务器页

### 列表

- 标题「MCP 服务器」，说明「让 Agent 调用外部工具。添加后立即连接，所有会话都能用。」
- 两列卡片网格（`repeat(auto-fill, minmax(240px, 1fr))`，gap 10px），卡片样式同「内置插件」页：`--dsw-alias-settings-card-fill` 底、0.5px `--dsw-alias-settings-card-stroke` 描边、`--dsw-radius-xl` 圆角、padding 12px 14px，hover 底色 `--dsw-alias-interactive-bg-hover`。
- 卡片内容：
  1. 第一行：状态点 + 名称（14px/500，单行省略）……右侧是启用开关（点开关不进入详情）。插件提供的服务器没有开关。
  2. 第二行：等宽 12px tertiary，`command args…` 或 URL，单行省略，`title` 显示全文。
  3. 第三行：状态文字（12px）+ 标签。状态文字：「已连接 · 12 个工具」、「连接中…」、「重试中（2/5）」、「连接失败」、「需要凭据」、「已停用」。失败 / 需要凭据时，下面再加一行红 / 黄色的错误摘要（单行省略）。标签：「本地」/「远程」，「内置配置」或「插件提供」。
  - 停用的卡片：名称和命令变成 tertiary 色。
- 网格下方：虚线整行按钮「+ 添加 MCP 服务器」（与「添加模型提供商」同款，44px 高，1px dashed `--dsw-alias-border-l3`，`--dsw-radius-lg`）。
- 空状态：没有任何服务器时，不显示空网格，直接显示「添加」视图的粘贴框（见下），标题写「添加第一个 MCP 服务器」。
- 服务器超过 6 个时，网格上方出现搜索框，按名称和命令 / URL 过滤。
- 读取失败：显示错误和「重试」，不能把读取失败显示成「没有服务器」。

### 添加（粘贴优先）

大多数 MCP 服务器的 README 给的是一段 JSON（`mcpServers`）、一条启动命令，或一个 URL。添加视图第一步就是一个粘贴框：

- 标题「添加 MCP 服务器」，等宽 textarea（4 行），占位文字「粘贴启动命令、服务器 URL 或 JSON 配置」。
- 下方实时显示识别结果（12px）：「识别为本地命令：npx」/「识别为远程服务器：mcp.example.com」/「识别为 JSON：3 个服务器」/「无法识别，请检查格式或手动填写」。
- 识别规则：
  - JSON：接受 `{"mcpServers": {...}}`、`{"mcp": {"servers": {...}}}`、`{"servers": {...}}`、`{名字: {command|url...}}`、单个不带名字的 `{command, args, env}` / `{url, headers}` / `{type: "http"|"sse"|"stdio"...}`。`type`/`transport` 为 `http`、`streamable-http`、`streamableHttp` 时是远程；`sse` 也按远程处理并提示「DSH 只支持 Streamable HTTP，SSE 服务器可能连不上」。允许 JSONC 的注释和尾逗号。
  - URL：以 `http://` 或 `https://` 开头、没有空格。
  - 其他：按 shell 规则拆成参数（支持单双引号、反斜杠转义、行尾 `\` 续行）。开头的 `KEY=VALUE` 段提取为环境变量。
  - 名字推导：JSON 用键名；命令里取最像包名的参数（`@scope/server-github` → `github`，`mcp-server-fetch` → `fetch`，`uvx xxx-mcp` → `xxx`）；URL 取主机名第一段（`mcp.notion.com` → `notion`）。规范化成 `[a-z0-9_-]`，最长 32，与已有名字冲突时加 `-2`。
  - 看起来像密钥的键（`TOKEN`、`KEY`、`SECRET`、`PASSWORD`、`AUTH`、`CREDENTIAL`，以及请求头 `Authorization`、`X-Api-Key`）自动标为「密钥」。
- 粘贴后识别到**一个**服务器 → 直接进入表单（预填，未保存）。识别到**多个** → 进入批量导入列表：每行复选框、名称、摘要；名字已存在的行显示「已存在」并给「跳过 / 覆盖」分段（默认跳过）；底部「导入 N 个」。
- 粘贴框下方还有一个文字按钮「手动填写」，打开空表单。

### 表单（添加和编辑共用）

字段从上到下：

1. **名称**（只在添加时可改；编辑时名字是标题）：等宽输入框，输入时规范化，提示「工具名前缀：mcp__名称__」。
2. **连接方式**：分段控件「本地命令」|「远程 URL」。
3. 本地命令时 **命令**：单行等宽输入框，显示完整命令行（参数按需加引号）。下方用小号参数块预览拆分结果（`npx` `-y` `@modelcontextprotocol/server-github`），让用户确认带空格的路径有没有被拆错。往命令框里粘贴 URL 会切到远程；往 URL 框里粘贴带空格的命令会切回本地。
   远程 URL 时 **URL**：单行输入框。
4. **环境变量**（本地）/ **请求头**（远程）：键值行编辑器。
   - 每行：键（等宽，环境变量键自动转大写）| 值 | 「密钥」切换（锁形图标按钮，`aria-pressed`）| 删除。
   - 密钥行的值框是密码框；已保存在凭据库里的密钥显示占位「已保存在凭据库」，留空表示保持不变，输入新值即替换；凭据缺失时值框下方黄色提示「凭据库里没有这个值，请重新填写」。
   - 值里只写了 `${credential:X}` 的行按密钥显示；部分模板（如 `Bearer ${credential:X}`）按普通文本显示。
   - 末尾「+ 添加环境变量 / 添加请求头」。
5. **高级**（折叠，`details`）：折叠时摘要只列非默认值，如「工作目录 ~/proj · 启动超时 60 秒」，全是默认值时写「工作目录、超时」。展开后：工作目录（仅本地）、启动超时（秒，占位 30）、工具调用超时（秒，占位写「默认」）。
6. 底部操作行：
   - 添加时：「取消」「添加并连接」（主按钮）。
   - 编辑时：「取消」「保存」，只有改动后才可点；旁边提示「保存后会重新连接」。
   - 校验错误显示在对应字段下方（12px，`--dsw-alias-state-error-primary`），并把焦点移到第一个出错字段。保存失败显示在操作行上方。

### 详情

- 顶部「‹ MCP 服务器」，标题行：名称（16px/500）+ 状态胶囊；右侧启用开关。
- 状态区：
  - 已连接：一行「已连接 · 12 个工具 · 3 分钟前连上」，不加卡片。
  - 失败 / 重试中 / 需要凭据：整块提示卡（错误红 / 警告黄的 10% 混色底），里面原样显示错误文字（等宽、可选中，超过 4 行折叠），按钮「重新连接」「测试连接」。
  - 已停用：一行灰字「已停用，Agent 现在用不到它的工具。」
  - 连接中：带转圈的「连接中…」。
- 工具区「工具（12）」：已连接时从 Host 读取当前注册的工具（名称 + 描述的第一行），超过 8 个时有过滤框。未连接时显示「连接后显示工具」和「测试连接」按钮；测试结果显示服务器名 / 版本、耗时和工具名列表。测试只单独连一次，不影响正在运行的实例。
- 配置区：上面的表单（插件提供的服务器只读，显示「由插件注册，不能在这里修改」）。内置配置的服务器在表单上方提示「这个服务器来自内置配置，你的修改会另存为覆盖。」并提供「恢复默认」。
- 底部危险操作：「删除服务器」（危险文字按钮）→ 确认对话框「删除 github？会从配置中移除它，并删除它保存在凭据库里的密钥。」确认按钮红色。内置配置的服务器没有删除，只有停用和恢复默认。

## 技能页

0.2 起技能页分两个标签：「已安装」和「技能仓库」。导入一律通过技能仓库：添加仓库链接 → 扫描 → 勾选安装；之后回到仓库里检查更新、一键更新。

### 页头与标签

- 标题「技能」，说明「技能是按需加载的任务说明。Agent 会根据描述自动使用，你也可以在输入框输入 / 调用。」
- 说明下面是分段标签 `已安装 | 技能仓库`（core `Segmented`，radiogroup 语义改成 tablist：`role="tablist"` / `role="tab"` / `aria-selected`）。有可更新的技能时，「技能仓库」后面带一个数字徽标（info 色小圆角数字，例如 `技能仓库 2`）。
- 当前标签、所在视图都存在 controller store 里；关掉设置再打开回到原处。

### 已安装（列表）

- 工具栏：搜索框（占满剩余宽度）+「选择」（次按钮，进入多选）+「新建技能」（主按钮）。没有可删除的技能时「选择」禁用。
- 项目选择、分组、行、徽标同 0.1。
- 来自仓库、有安装记录的行多两个徽标：仓库名（neutral，例如 `anthropics/skills`，tooltip「从技能仓库 anthropics/skills 安装」）；有更新时「有更新」（info）；本地改过时「已修改」（outline）。
- 空状态：「还没有技能」+「新建技能」「浏览技能仓库」（切到仓库标签）。

### 已安装（多选删除）

- 点「选择」进入多选模式：工具栏换成「已选 N 个」+「全选」（只选可删除的、当前搜索可见的）+「取消」；
- 每个可删除行（`editable`）左侧出现复选框，点整行切换选中；不可删除的行（内置、只读）变淡、不能选；有分组时组标题右侧有该组的「全选」复选框（支持半选）。
- 底部固定一条操作栏（sticky，在设置内容列底部，卡片底色 + 上边框）：左「已选 N 个」，右「删除 N 个」（危险实心按钮，N=0 时禁用）。
- 确认对话框「删除 N 个技能？」，正文列出名称（最多 8 个，多余写「等 N 个」），说明「会删除这些技能的整个目录。」；选中项里有 `*-agents` 位置的，加一句「其中 M 个在通用目录里，Claude Code、Codex 等工具也会失去它们。」确认按钮「删除」（红色）。
- 删除完成：退出多选，顶部结果行「已删除 N 个」；有失败时 warn 色并列出「x：原因」。
- Esc 退出多选（没有对话框时）；切标签、进入详情也退出多选。

### 详情 / 编辑

- 同 0.1。来自仓库的技能多一条 info 横幅：「从技能仓库 **anthropics/skills** 安装（skills/pdf）」+ 按钮「查看仓库」（切到仓库标签并打开该仓库详情）。有更新时横幅变成「技能仓库里有新版本」+「更新」（主按钮，小）；本地改过时再加一句「你在本地改过这个技能，更新会覆盖这些修改。」，点「更新」先弹确认。
- 有未保存修改时不能更新（按钮禁用并提示先保存或取消）。

### 技能仓库（列表）

- 顶部添加区（`module` 底色卡片）：标题「添加技能仓库」，一行输入框（等宽，占位「GitHub 链接、git 地址或本地文件夹」）+「添加」主按钮；回车也能添加。添加中按钮 busy，下面写「正在下载仓库…」（git）或「正在读取文件夹…」。失败在输入框下方红字显示 Host 的原因。
- 输入框下面是「推荐」行：可点击的小卡片 / chip，点了直接添加（已添加的不显示）：
  - Anthropic · `anthropics/skills`（subpath `skills`）
  - OpenAI · `openai/skills`（subpath `skills/.curated`）
  - Matt Pocock · `mattpocock/skills`
  - Cursor · `cursor/plugins`（subpath `pstack/skills`）
- 已添加的仓库是一列行卡片（同已安装列表的行样式）：左侧图标（git：分支图标；本地：文件夹），名称（14px/500），下面 12px tertiary 一行「12 个技能 · 已安装 3 · 2 小时前检查」；右侧徽标「2 个可更新」（info）或「检查失败」（error，tooltip 是原因）；最右 chevron。点击进入仓库详情。
- 列表上方右侧「检查全部更新」（次按钮，小）：依次刷新所有仓库，按钮显示进度「正在检查 2/4…」，完成后结果行「检查完毕，3 个技能有更新」。
- 添加成功（或已存在）直接进入该仓库详情。

### 技能仓库（详情）

- 顶部「‹ 技能仓库」。标题：仓库名；副标题：来源（等宽，可选中）；GitHub 仓库多一个「在 GitHub 打开」链接（`target=_blank rel=noreferrer`）。右侧「检查更新」（次按钮，busy 时「正在检查…」）。
- 元信息一行（12px tertiary）：「提交 abc1234 · 5 分钟前检查」；`lastError` 时显示 warn 横幅「上次检查失败：原因」+「重试」。
- 打开详情时，如果上次检查超过 24 小时，自动后台检查一次（元信息行显示转圈「正在检查更新…」，不阻塞列表）。
- 有可更新技能时，info 横幅「N 个技能有更新」+「全部更新」。
- 技能多于 8 个时有过滤框。
- 技能行（可勾选）：复选框、名称、状态徽标、一行描述；已安装的行在描述下面一行列出安装位置（例如「个人 · DSH 专用」）。状态徽标：
  - 未安装：无徽标
  - 已安装（有记录且最新）：「已安装」（success）
  - 有更新：「有更新」（info）；本地改过再加「已修改」（outline）
  - 同名技能已存在（没有本仓库的记录）：「同名已存在」（warn，tooltip 列出位置）
  - 无效：「不可安装」（error）+ 原因，行禁用
  - 跨位置覆盖的方向提示同 0.1 的导入（「会被覆盖」「覆盖同名」）。
- 默认不勾选任何行（仓库可能很大）。表头一行「全选」（只选当前过滤可见、可操作的行）+「已选 N 个」。
- 底部 sticky 操作栏（有选中时出现）：左「安装到 [位置 ▾]」（只有选中了未安装 / 同名已存在的行时显示），右侧按钮：
  - 「安装 N 个」：选中的未安装行 + 同名已存在行。同名已存在的行在选中时出现「跳过 / 覆盖」分段（默认跳过），和 0.1 一样。
  - 「更新 N 个」：选中的有更新的行（更新它的所有已记录副本）。选中项里有本地改过的 → 先弹确认「M 个技能在本地改过，更新会覆盖修改」，按钮「仍然更新」/「跳过改过的」/「取消」。
- 安装 / 更新完成：结果行（同 0.1，「已安装 2 个，更新 1 个，跳过 1 个」），表格就地刷新、清空选择，刚变化的行短暂高亮。
- 底部危险区：「移除仓库」→ 确认「移除 anthropics/skills？已安装的技能会保留，但以后不能从这里检查更新。」

## 视觉规则

- 只用 `--dsw-*` token；控件样式照抄宿主（见 `client/00-core.js` 的 CSS），不引入 Harness Client 包。
- 字号：页面标题 16/24 500；分区标题 14/22 500；正文 14/22；说明 13/20 或 12/18 tertiary；等宽 12/18。
- 间距：分区之间 20px，分区内 12px，字段内标签与控件 6px。
- 按钮：主按钮 `--dsw-alias-button-primary-fill`；次按钮 0.5px `--dsw-alias-border-l3` 描边；危险按钮红字透明底。高度 32px（页面操作）/ 28px（卡片和行内）。
- 状态色：成功 `--dsw-alias-state-success-primary`，警告 `--dsw-alias-state-warn-primary`，错误 `--dsw-alias-state-error-primary`，空闲 `--dsw-alias-state-idle-primary`。
- 动效：视图切换 120ms 淡入 + 4px 位移；开关 120ms；转圈图标；`prefers-reduced-motion` 时全部关闭。
- 文案：中文和英文都要写，英文用 sentence case。

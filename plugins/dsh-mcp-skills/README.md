# @pcmid/dsh-mcp-skills

在 DSH 设置里增加「MCP」和「技能」两页，不用手写配置文件就能添加、测试、修改和删除 MCP 服务器与技能，并从技能仓库安装和更新技能。交互参考了 OpenChamber 的同类设置页，设计说明见 [docs/design.md](docs/design.md)。

## MCP

- **粘贴即可添加。** 粘贴框能识别三种来源：启动命令（`npx -y …`、`uvx …`、`docker run …`，开头的 `KEY=VALUE` 会变成环境变量）、`https://` 服务器地址，以及 Claude、Cursor、VS Code 配置里的 `mcpServers` JSON。名称会自动推导。JSON 里有多个服务器时进入批量导入，同名的可以选择跳过或覆盖。也可以手动填写。
- **密钥不写进配置文件。** 环境变量和请求头可以标成「密钥」，看起来像密钥的键（`TOKEN`、`API_KEY`、`Authorization` 等）会自动标上。值存进 DSH 凭据库，配置里只留 `${credential:MCP_<服务器>_<键>}`。删除服务器时，它自己的密钥也会一起删掉。
- **状态实时可见。** 卡片显示连接状态和工具数量，失败或重试时直接显示错误摘要。卡片上的开关可以停用或启用服务器，配置会保留。
- **需要登录授权的服务器（OAuth）。** 添加远程 URL 时会先检查服务器是否要求授权：
  - 要 OAuth 时按钮变成「添加并授权」，保存后在浏览器打开授权页，授权完成自动连接。
  - 只要访问令牌（401 但没有 OAuth）时，提示在请求头里填写。
  - 已添加的服务器返回 401 时，卡片和详情页显示「需要授权」和「授权」按钮。

  技术细节：
  - 授权按 MCP 授权规范走 OAuth 2.1 授权码 + PKCE，支持动态注册客户端；不支持动态注册的服务器可以手填 Client ID。
  - 回调地址是本机临时监听的 `http://localhost:<端口>/callback`；浏览器跳不回来时，可以把回调 URL 粘贴回设置页完成授权。
  - 访问令牌存进凭据引用 `MCP_<服务器>_OAUTH`，配置里只有 `Authorization: Bearer ${credential:…}`。refresh token 存在 DSH 凭据库的授权记录里，到期前 2 分钟自动续期。
  - 详情页可以重新授权或退出授权。
- **重试策略：首次连接失败不自动重试，连上过之后断开才自动重连。**
  - 首次失败后服务器停在「连接失败」，等你点「重试」。
  - 连接成功过的服务器断开后，本插件按 1、2、4 … 30 秒退避自动重连，最多 10 次，期间显示「重新连接中（n/10）」。
  - 实现方式：本插件保存的服务器会写入 `reconnect: { enabled: false }`，关掉 DSH 自带的重试，由插件接管。手写配置、没有这一项的服务器仍按 DSH 默认行为重试。
- **详情页：**
  - 状态与错误：显示完整错误，可以「重新连接」。
  - 工具列表：直接读取 Agent 当前拿到的工具，包括名称和描述，不会多启动进程。
  - 测试连接：服务器还没连上或已停用时，可以单独连一次，看它提供哪些工具，不影响正在运行的实例。
  - 编辑与删除：可以修改配置、删除服务器。
- **写入位置。** 配置通过设置表单写入内置 `mcp-manager` 条目的 `servers`，与手改 `cordis.patch.yml` 效果相同。保存后对应服务器会重新连接，其他服务器不受影响。

## 技能

- **一个列表看全所有来源。** 按「项目 · <工作区>」「个人」「内置」分组，显示每个技能来自哪个目录。同名技能里优先级低的那个会标「被覆盖」。「内置」只读，默认折叠。
- **新建和编辑：**
  - 名称、描述、使用时机和正文都可以编辑。
  - 「Agent 使用方式」有两种：自动，或仅在你输入 `/名称` 时加载（对应 `disable-model-invocation`）。
  - 也可以设置是否允许用 `/名称` 调用（对应 `user-invocable`）。
  - 编辑时只改这几个键，frontmatter 里的其他键和注释原样保留。
- **存放位置可选**，默认是上次选的位置，第一次是「个人 · DSH 专用」：

  | 选项 | 目录 | 说明 |
  |---|---|---|
  | 个人 · DSH 专用 | `~/.dsh/skills` | 只有 DSH 读取 |
  | 个人 · 通用 | `~/.agents/skills` | Claude Code、Codex 等也会读取 |
  | 项目 · DSH 专用 | `<项目>/.dsh/skills` | 项目根是工作区往上最近的含 `.git` 的目录 |
  | 项目 · 通用 | `<项目>/.agents/skills` | |

  同名时优先级从高到低：项目 DSH 专用、项目通用、个人 DSH 专用、个人通用、内置。
- **多选删除。** 「已安装」里点「选择」进入多选，勾选后底部「删除 N 个」一次删掉；内置和只读的技能不能选。每组有自己的「全选」。
- **技能仓库。** 「技能仓库」标签里添加仓库，从仓库安装技能，之后在仓库里检查和安装更新：
  - 支持 GitHub 仓库或子目录链接（如 `github.com/anthropics/skills/tree/main/skills/pdf`）、其他 git 地址和本地文件夹；也可以一键添加推荐仓库（Anthropic、OpenAI、Matt Pocock、Cursor）。
  - 仓库详情列出所有 `SKILL.md`，标出未安装、已安装、有更新、本地已修改、同名已存在、不可安装（例如 Anthropic 的 docx/pdf/pptx/xlsx 有许可证限制）。勾选后选择位置安装，或更新有新版本的技能。
  - 更新会覆盖整个技能目录；在本地改过的技能会先确认，可以「跳过改过的」。
  - 打开超过 24 小时没检查的仓库时会自动检查一次；列表页可以「检查全部更新」。「技能仓库」标签上的数字是可更新的技能数。
  - 从仓库装的技能在「已安装」里带仓库名，有更新时显示「有更新」，详情页可以直接更新或跳到仓库。
  - 移除仓库不会删除已安装的技能，只是不再能从这里更新。
  - 仓库列表和安装记录存在 `~/.dsh/mcp-skills/state.json`，git 仓库的副本缓存在 `~/.dsh/mcp-skills/repos/`。「有更新」「已修改」靠比较内容哈希判断，与提交号无关。
- 改动后 DSH 会自动重新发现技能，不用重启。

## 实现

- Client 半边是 `client.js`，由 `client/*.js` 拼接生成：改完运行 `npm run build`，用 `npm run check` 检查 `client.js` 是不是最新的。
- Host 半边是 `index.js` 和 `host/`，提供两组接口，MCP 和技能各一组：`POST /api/mcp-settings/<操作>`、`POST /api/skill-settings/<操作>`，只有 owner 能访问。接口见 [docs/host-api.md](docs/host-api.md)。
- 所有写入和删除都限制在上表四个技能目录的直接子目录里，并在 Host 端检查。Git 克隆和更新不经过 shell，非交互运行，90 秒超时。
- 插件配置（只能在 `cordis.patch.yml` 里改，`id: mcp-skills`）：

  | 字段 | 默认值 | 含义 |
  |---|---|---|
  | `reconnectAfterConnected` | `true` | 连上过的服务器断开后自动重连；设为 `false` 后本插件保存的服务器断开就停住，等手动重试 |
  | `reconnectMaxAttempts` | `10` | 每次断开最多自动重连的次数 |

  授权与重试的接口约定见 [docs/auth-retry.md](docs/auth-retry.md)。

## 已知限制

- **MCP 进程的 stderr 看不到。** DSH 的 mcp-client 只报告 `Connection closed` 这类连接层错误，不会把服务器进程的 stderr 传上来，所以「命令写错」「缺少依赖」这类问题只能看到笼统的错误。
- **OAuth 只支持远程（Streamable HTTP）服务器，回调只能落在运行 DSH 的这台电脑上。** 在别的设备上打开授权页时，要把回调 URL 粘贴回设置页。不支持 DPoP 和 Client ID Metadata Document。
- **自动重连状态只在 DSH 运行期间有效。** DSH 重启后，服务器启动时连不上算「首次失败」，不会自动重试。
- **只支持 Streamable HTTP。** 只提供 SSE 的旧服务器可能连不上，粘贴时会提示。
- **MCP 服务器和技能都不能改名。** 要改名就新建一个、再删掉旧的。
- **内置配置里的服务器不能切换连接方式，也不能删除。** Settings 删不掉下层配置里的键，所以只能修改、停用或恢复默认。
- **技能没有「完全关闭」。** 「仅手动调用」能让技能不进 Agent 的技能目录。真要停用只能删除，或者移出这些目录。
- **技能仓库不支持需要登录的私有仓库。** Git 以非交互方式运行，只能用本机已有的 git 凭据（例如 SSH key、credential helper）；需要输入密码的会失败。
- **检查更新会下载仓库最新版本的完整快照**（`--depth 1`），大仓库第一次添加会慢一些。
- **改 `~/.agents/skills` 里的技能会影响其他工具。** Claude Code、Codex 等读取同一份文件，页面上会提示。
- **没有提供给 agent 的工具。** 添加 MCP 服务器相当于允许运行任意命令，所以只能由用户在设置页操作。Agent 本身可以直接读写技能文件。
- **在详情页点左侧导航的同一项，不会回到列表。** 要用页面上的「返回」。
- **依赖 Chromium 的 Popover 和 CSS 锚点定位**，Harness 自带的菜单也依赖它们。
- **文案只有中文和英文**，其他语言显示英文。

## 测试

```sh
npm install --no-save --no-package-lock   # 无依赖，可跳过
npm test                                   # Host 路由、frontmatter、导入、前端解析与控制器
npm run check                              # client.js 是否与 client/*.js 一致
```

# SuperAgent

每条获准办理的飞书消息是一个事项。Router 只分流；承办助手读取会话上下文、处理请求，必要时在原会话向提需人追问，答复前由承办助手自己核对结果。工作区展示原消息、办理状态、承办助手的答复和飞书回执，不是另一个聊天框。打开事项，每条原消息下默认展开「办理过程」：可看实际分派和助手办理，以及 Router 和承办助手会话的「会话记录」：提需人的回复、你接手后发的消息、模型输出的文字，以及助手通过工具发出的答复和追问（办理中实时更新；不含思考、其他工具调用和结果、SuperAgent 自己的指令，也不含子 agent 的对话）。「事项材料」里的「带入的上下文」按时间列出交给助手的同话题消息，发言人与助手看到的一致，显示为提需人、你或参与者编号。答复和原话题回执单独展示，收起过程后仍可核对。旧消息只展示已记录的状态。桌面使用列表与详情双栏，手机先显示列表。

## 使用

1. **DSH 设置 → SuperAgent → 团队分工**：Router、开发助手、答疑助手各有独立的原生预设。首次应用时只补尚未设置的绑定；已选用的 DevLoop 等个人预设不被覆盖。当前默认供应商是 `codex-provider` 时，对照其模型目录，分别选用 `gpt-6.2-astra / high`、`gpt-6.2-astra / xhigh` 和 `gpt-6-luna / medium`。目录里没有的型号和档位不写入；这里的选择不改变 DSH 全局默认。以后可分别更换；清空绑定即使用原生默认，重启不重新填入。角色说明各自在 [预设声明](./cordis.patch.yml) 中，修改后重新应用 bundle，新会话采用新版。随附预设带有工具：Router 只能只读查看和搜索本机文件，用于判断该放进哪个工作区，不能改文件、跑命令或上网；开发助手和 DSH 标准会话一样，可用命令行、读写文件、搜索、后台任务、技能、网页、待办、子 agent 和上下文压缩；答疑助手可读文件、搜索、上网、用技能、处理 Office 文档，也可用命令行做查询，但不能写入或编辑文件。三者都没有本机提问、计划模式、定时任务和插件管理工具。
2. **飞书 → 连接飞书**：首次连接按飞书官方页面提示创建专用应用、授权本人，已有绑定沿用原应用。不需要输入应用名、密钥、群 ID 或会话内容。默认从 Host 的 `PATH` 启动 `lark-cli`；若桌面端找不到它，在同页「lark-cli 可执行文件路径」填写本机可执行文件的绝对路径，清空即可恢复默认。授权、轮询和回复共用此设置，无需重新绑定。凭据由本机 lark-cli 管理；创建应用、绑定本人和批准群是三件不同的事。授权允许读取身份、群信息和消息、搜索 @本人，并以本人身份回复。旧的只读绑定不会自动升级。
3. **飞书 → 轮询间隔**：Host 通过系统 `lark-cli` 以本人身份在内部群和飞书「与自己的聊天」里检查新提及，默认每分钟一次（可设 1–1440 分钟）。「接收他人私聊」默认关闭；打开后，对方新发来的一对一消息不需要 @。你发给对方的普通消息不是新需求；在已开启的私聊里明确 @自己是例外。「与自己的聊天」仍需直接 @自己，不依赖此开关。关掉再打开，不补采关闭期间的私聊。不用打开 DSH 设置、选群或手动同步，不接机器人事件，也不由插件直连飞书 HTTP API。
4. **SuperAgent → 动态**：收到的请求逐条显示，点开即可看正文，不需要先批准。别人的私聊与群里别人 @你一样，未有办理授权时先在动态待批。你亲自在内部群、「与自己的聊天」或已开启收件的私聊里明确 @自己，则自动走「授权一次」：只把该话题交给助手，不永久授权会话，不连带办理先前其他待批消息。支持文本和富文本中的可读内容；不会展开转发正文，群内仅 @全员 不触发。SuperAgent 自己发出的回帖不会作为新请求再次办理。尚未获得办理授权的消息只进入动态，不建事项、不交给助手、不回帖。可在消息上用两个下拉菜单处理。「授权」：「授权一次」只办理本话题及其后续；「永久授权」覆盖整个会话；「仅授权此用户」只办理这条消息的发送人在本会话的消息，别人的仍待批。核实原消息仍符合收件条件后，按动态里留存的正文办理你选中的那条。之后范围内的新请求自动办理；不会把其余待批消息一起送给助手。「忽略」：「忽略一次」只略过这条，同一话题之后的新消息仍会待批；「永久忽略」后这个群或私聊之前待批的消息从动态里移走，之后的消息不再读取、不进动态、不交给助手，直到你取消忽略。会话已有永久授权或成员授权时需要先撤销才能永久忽略。
   有飞书原生线程时，Router 和承办助手都收到原消息及办理时该线程的根消息和可读回复，包括原消息前后的同线程讨论。上下文本身不创建新事项；私聊开关的生效时间限制哪些消息可以成为新请求，不会截断一条已获准请求明确所属的原生线程。没有原生线程时，才使用**设置 → SuperAgent → 飞书**中的历史条数和分钟数：默认取触发消息前 5 分钟内最近 10 条，两项同时生效，任一设为 0 就不补这部分前文。不会下载附件或展开转发；线程过长而无法完整交给助手时显示错误，不把一截当成全文。
5. **团队分工 → 对外发送前需我确认**：默认开启。每次追问、每次最终答复都单独适用此开关。在「动态」或「事项」核对要发送的正文和原目标，再确认或拒绝。关闭开关不会放行已经在等待确认的内容。该设置与群或话题的收件授权独立。
6. **设置 → SuperAgent → 飞书**：查看和撤销永久授权与成员授权，每个群或私聊一行，成员授权另起一行并注明授权时那条消息；「授权一次」产生的话题授权不在这里列出。已忽略的会话单独列出，可「取消忽略」，之后的新消息重新进入动态，忽略期间的消息不会补办。点击会话名可打开飞书；查看详情或设置不会启动办理。轮询失败后可在账号状态下展开「错误日志」，查看这个绑定最近 20 条错误的时间、步骤、原因和飞书错误码（若有）。恢复后仍可查看；不保存消息正文、账号标识或命令输出。暂停来源不会注销飞书账号。

## 一条请求如何交付

Router 只决定是否接单、分配给开发还是答疑助手，以及承办助手在哪个 DSH 工作区办理，不制定验收标准、追问或验收。工作区从 DSH 里已登记的工作区中选（例如请求里提到的项目或仓库），承办会话就建在那个工作区里，也会出现在 DSH 侧栏该工作区下；没有明确合适的就用 SuperAgent 自己的工作区。Router 自己的会话始终在 SuperAgent 工作区。

**同一话题的后续消息：**每次直接 @ 都先交给 Router。同一会话里已有未结束的事项（有原生线程时按同一线程，没有线程时按同一会话里同样不在线程里的消息；线程里已经回复过的事项也算），Router 会看到这些事项的请求、状态和已拟或已发的答复，再选择：作为补充**并入**原事项、作为新事项办理，或忽略。并入时，原事项的承办助手在同一会话里带着这条新消息继续：正在办的会被打断后接着办；已拟好但未发送的答复或追问作废后重拟；等提需人回复的追问撤回；线程里已经回复的事项重新打开，新答复作为新消息发送，仍按外发确认放行。被并入的消息在「动态」里显示「已并入其他事项」，不单独成为事项。Router 分派和承办助手办理并行进行，新消息不用等前一个事项办完才得到判断。承办方是实际的 DSH 会话；DevLoop 是可选助手，不是消息源或审批人。缺少办理所需的上下文时，承办助手拟好问题，按外发策略回复原消息。问题只问提需人才知道的事实，例如指的是哪个系统、文档、版本或报错；不让提需人选方案或做决定，方案由承办助手自己定，并在答复里写明假设。这条规则写在助手的指令里，由模型遵守，SuperAgent 不另做检查。收到提问的飞书回执后，事项进入「等待提需人回复」，不算交付。原提需人直接回复那条问题即可，不需要再 @；其回复回到同一事项、同一个承办会话，不重新分流。没有单独的验收步骤：承办助手自己核对结果后给出最终答复，外发仍须遵守当前策略。

人工确认和收到飞书回执是两个不同的状态。人工确认只放行这一次的追问或答复和原目标，不授予以后发件的权限。只有在重新核对账号、当前授权、原群和消息，并拿到匹配的飞书回执后，工作区才显示「已交付原话题」。回执不确定不盲重发；运行中断时不从私人会话补猜输出。旧案保留原有历史状态，不自动重办；升级前停在验收阶段的事项会显示为「办理中断」。工作区不复制模型推理，原生承办会话保留其自己的记录。

**需要你处理时的提醒：**左侧栏 SuperAgent 图标右上角出现黄点，表示有事要你处理：有消息等你批准、有追问或答复等你确认发送、承办助手正在等 DSH 原生工具审批，或未归档的事项办理失败。处理完（失败的事项可重试、接手或归档）黄点消失；归档只消除失败的提醒，等你确认发送的内容即使归档了也会提醒。页面在后台时不检查。

**归档、重试与接手：**「事项」列表每行右侧的「⋯」（与 DSH 普通会话相同，桌面悬停显示，手机常显，也可右键）里有「接手」「重试」和「归档」。接手后，正在办理的停下，承办会话变回普通 DSH 会话并直接打开，你在里面继续；SuperAgent 不再办理这条消息，也不再向飞书发送任何内容，等待中的追问和答复一并作废，飞书由你自己回复。回帖进行中的消息不能接手。归档后事项从列表中隐藏，它的 Router 和承办会话也一并归档（正在办理的会停下）；消息仍在「动态」里，等你确认发送的内容仍可放行。Router 做出分派决定后，它的会话会自动归档。只有当前飞书绑定下、能在「动态」里找到的事项才可归档。办理失败的消息（判断失败、办理失败或办理结果未确认）可从「⋯ → 重试」重新办理，作用于该事项里最近一条失败的消息：还没分派承办助手的，重新交给 Router 分流；已经分派的，在原承办会话里让助手接着办，它能看到之前的进度和工具结果。可能已经回帖的（送达结果未确认）、无需处理的和你选择不发送的不能重试。

**工具与权限：**Router 和承办助手按所选 DSH 预设使用工具，权限完全由 DSH 原生策略决定：允许的直接执行，要求审批的走 DSH 原生审批，禁止的不执行。SuperAgent 不另设工具名单或逐次批准，飞书请求也不能改变预设或权限。工具可能在拟写答复前就执行；「对外发送前需我确认」只决定是否把追问或答复发到飞书，不会撤销已执行的操作。

**结果通过工具交回：**每轮办理时，SuperAgent 只在该席位的会话里临时加几个结果工具，本轮结束即撤销：Router 用 `superagent_route`（作为新事项分给开发或答疑助手，可选工作区）、`superagent_merge`（并入同话题已有事项）或 `superagent_ignore`；承办助手用 `superagent_answer`（答复）或 `superagent_ask_requester`（追问提需人），必须有明确输出：无法办理时也要用答复说明做不到什么、为什么。结果在 DSH 记下该调用成功后才算数，本轮随即结束；同一步里多次调用也没关系，都会记录，以最后一次成功的为准。只有调用结果工具才算完成：助手只回了文字、或输出到长度上限就停下时，SuperAgent 在同一会话里提示它继续，直到它交回结果，不需要你介入。普通会话和已接手的会话里没有这些工具。

## 运行与验证

支持 **DSH 0.2.2-rc.3 和 rc.5**，飞书接入按 **lark-cli 1.0.100** 开发。Host 运行、本人已连接并授权自动办理后即轮询，即使还没有已批准的群。首次升级从启用新发现机制时起算，后续重启使用已保存的时间窗；暂停或换绑不沿用旧的触发凭据。身份、应用配置和准入代次不匹配即停止。只读绑定没有后台飞书 I/O。可信 Host 接入方可通过 `superagentRequests.requestAccess` 提出话题准入，不可用它批准、投递正文或回复。网页没有能造入站消息或指定发送目标的 RPC。

角色、事项、准入和投递仍使用原 Host 存储（v7，兼容 v1–v6；写入后旧版不能打开）。动态正文单独保存在本机，按飞书绑定和授权代次隔离；查看设置不会查询这份正文存档。工作区只展示真实记录，没有消息时显示空状态。

```sh
npm install --no-save --no-package-lock
npm run build && npm test
npm pack --dry-run
```

macOS 对应版本的 Desktop 可以离线用 `node test/automation-smoke/run.mjs` 验证收件、所选预设的工具按 DSH 原生策略执行（允许、审批、禁止）、原会话跨进程续办、追问与最终答复分别放行，以及回执防重发。测试只使用合成飞书消息、无副作用的测试工具和脚本模型，不接触个人账号。另有 `node test/smoke/run.mjs`（原生会话预设、冷启动续办）、`node test/settings-smoke/run.mjs`（设置持久化）和原生存储迁移检查。

# @pcmid/dsh-folder-browser

添加或打开工作区时，用应用内的文件夹选择框选目录，不再弹出系统文件管理器。

DSH 自带的目录选择在启动时自动判断：Host 只监听本机地址、有图形桌面时，就调用系统的文件夹对话框。通过远程方式（例如 dsh-remote-relay）打开 DSH 时，Host 依旧满足这些条件，于是对话框弹在 Host 那台机器的屏幕上，远程这边什么也看不到。本插件固定使用 DSH 自带的浏览后端，并换上自己的选择框。

## 用法

在侧边栏添加工作区、在工作区选择器里打开新目录，或在新会话页选择工作区目录时，弹出选择框。样式参考 VS Code 远程的「打开文件夹」和 Raycast 这类命令面板：

- **顶部是路径输入框**，既显示当前位置，也用来筛选。从主目录 `~/` 开始。
  - 输入名称即时筛选当前目录，前缀匹配排在前面，匹配部分加粗。
  - `↑` `↓` 选择，`Tab` 或 `↵` 进入高亮的文件夹。
  - 没有高亮项时按 `↵` 打开当前文件夹；`⌘↵`（其他系统 `Ctrl+↵`）直接打开高亮项。
  - 末段为空时按 `Backspace` 回到上一级。
  - 可以直接粘贴或输入 `/` 或 `~` 开头的完整路径。
- **常用位置**：主目录、已有工作区所在的上级目录（按工作区数量排序，最多 4 个），以及根目录 `/`。
- **列表**：点一行进入；鼠标悬停或键盘高亮时行尾出现「打开」，直接选中这一项。已经是工作区的目录带「工作区」标记。
- **新建文件夹**：输入一个不存在的名称时，提示没有匹配，并在列表末尾给出「新建文件夹"名称"」。它不会被默认选中，按 `↓` 选中后再按 `↵` 才创建并进入，打错字直接回车不会建出目录。也可以点底部的「新建文件夹」，在列表顶部输入名称。
- **目录太大**：Host 单次最多列出 1000 项（见下）。列不全时顶部会提示；输入没列出的名称时给出「进入"名称"」而不是新建，也可以直接输入名称加 `/` 进入。
- **加载中不误操作**：输入新路径后，上一层的列表会变暗保留到新列表到达，期间回车、点击都不生效，避免打开错的文件夹。添加工作区的过程中整个选择框锁定，主按钮显示「正在打开…」。
- 底部的眼睛按钮切换是否显示隐藏文件夹；输入以 `.` 开头的名称时会自动包含隐藏文件夹。
- 底部的主按钮写明将要打开的文件夹，如「打开 dsh-plugins」。`Esc` 先关闭新建行，再关闭选择框。

浏览的是 DSH Host 所在机器上的目录，与浏览器在哪台设备上无关。在手机等触屏设备上，打开时不自动弹出键盘（接了实体键盘时照常聚焦），行和按钮加高到便于点按的尺寸，输入框字号不小于 16px 以免 iOS 自动放大，快捷键提示和行尾的「打开」隐藏（点进文件夹后用底部按钮打开）。输入法上屏的回车不会触发操作。读屏软件可以通过输入框的说明听到快捷键。

## 实现

- 补丁停用 web-app 自带的 `directory-picker` 行（`@deepseek-ai/dsh-host-directory-picker-auto`），只加入本插件这一行（`folder-browser-ui`）。
- `index.js` 是 Host 端：把 DSH 自带的浏览后端 `@deepseek-ai/dsh-host-directory-picker-browse`（在 Host 上列目录、建目录）作为子插件挂上，它跟着本插件一起卸载。`directoryPicker` 同一时间只能有一个提供者，而运行中安装或启用时，DSH 会同时停用 `directory-picker` 行和启动本插件，系统对话框后端可能还没卸载完；Host 端会等它放开 `directoryPicker` 再挂浏览后端，所以不用重启。
- `client.js` 填充 `ui-workspace` 声明的三个目录选择位置（`conversation.hero.workspace.directoryFlow`、`sidebar.workspaces.directoryFlow`、`workspace.picker.directoryFlow`），通过 `ctx.uiWorkspace.listDirectory` / `createDirectory` 读写，用原生 `<dialog>` 显示，样式只用主题变量，深浅色主题都跟随 DSH。
- 打开过的目录在本次选择期间缓存，前进后退不再请求；新建后刷新上级目录。

停用或卸载本插件后，重启 DSH 即恢复自动判断（运行中停用见「已知限制」）。

## 测试

```sh
npm install --no-save --no-package-lock
npm test
```

- `test/client.test.mjs`：在 jsdom 里用 deepseek-harness 检出中的 React 驱动选择框（需要同级或上级目录有构建过的 deepseek-harness，或用 `HARNESS_DIR` 指定），覆盖筛选、键盘导航、Tab 补全、退回上级、打开、新建（含打错字不误建）、加载中的旧列表不可操作、输入法回车、目录过大时的「进入」、常用位置、错误提示、忙碌锁定和 Esc。
- `test/host.test.mjs`：用 devDependencies 里的 Cordis 和浏览后端，覆盖空闲时直接挂上（含 `maxEntries` 透传）、被占用时等待并在放开后接手、旧后端还在卸载时启动（0.1.0 的独立后端行在这里会失败）、等待中被卸载后不再挂，以及旧后端放开的同一时刻本插件被停用或因改配置而重载时不抛出未捕获的异常。

## 已知限制

- **本机也不再用系统对话框。** 选择方式在 Host 启动时整体确定，不能按浏览器所在设备区分。
- **运行中停用或卸载后需要重启。** 这时 DSH 恢复 `directory-picker` 行和卸载本插件是同时进行的，系统对话框后端可能在浏览后端放开 `directoryPicker` 之前启动，报 `service "directoryPicker" has been registered` 后不再重试，选择框随之不可用，重启 DSH 即可恢复。要根治，需要 DSH 的 `directory-picker-auto` 也等前一个后端放开再挂，插件这边修不了。
- **只能浏览和新建目录。** 不能重命名或删除；筛选只在当前目录内、已列出的项里进行，不做跨目录搜索。单个目录最多列出 1000 项（`maxEntries`，可在 `folder-browser-ui` 行的 `config` 里调整）。
- **大小写**：筛选不区分大小写；判断名称是否已存在时，Windows 和 macOS（主目录在 `/Users/` 下）不区分大小写，其他系统区分。
- **文案只有中文和英文**，其他语言显示英文。
- 依赖 web-app 包里行 id `directory-picker` 不变；如果 DSH 以后改名，补丁会被跳过并在日志里警告，此时系统对话框后端一直占着 `directoryPicker`，Host 端只在日志里说明在等它，选择框会报需要浏览后端。

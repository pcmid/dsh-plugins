# @pcmid/dsh-agent-monitor

在输入框上方加一条「智能体」，列出当前会话里每个智能体在做什么：运行中、等待后台工作，还是空闲。它只显示，不参与调度，除了展开和收起没有别的操作。

## 显示什么

默认收起，只有一行：图标、「智能体」、各状态的数量，例如 `2 个运行中 · 1 个等待后台工作 · 1 个空闲`。有待处理消息的智能体算在空闲里。和 Harness 的任务列表一样，点一下展开，再点一下收起。

展开后每个智能体一行，子智能体按谁创建了它逐级缩进：

- **状态标记**：运行中是转动的圆环，等待后台工作是暂停标记，其余是圆点。
- **名称**：会话自己的智能体显示「本会话」；子智能体显示模型称呼它用的名字（例如 `builder/checker`），没有名字的显示会话 ID 的前 8 位。名称后面是创建它时写的任务说明。
- **右侧**是它在做什么和持续时间。运行中的从这一轮开始算起，其余从上一轮结束算起。
  - 运行中：正在执行的工具调用，例如 `bash · npm test`；没有工具调用在执行时显示「思考中」。
  - 等待后台工作：它自己停下了，但它启动的后台任务还在运行或正在停止，或者它创建的子智能体还加载着。
  - 有待处理的消息：它停下了，但还有发给它的消息没处理。
  - 空闲。
- **后台任务**：智能体下面列出它还没结束的后台任务，每个一行：类型和名称（`bash` 任务是命令的第一行），以及已运行多久。最多列 3 个，其余显示「另有 N 个」。还在前台执行的命令不是后台任务，不列在这里；超时转入后台之后才列出来。
- **目标**：会话有进行中的目标（不是待继续、已暂停或受阻的）、轮数还没用完，而会话的智能体停着、后台工作还没结束时，「本会话」下面多一行「目标：等待后台工作，之后开始下一轮」。后台工作指它自己的后台任务，或者还在运行、还在等待后台工作的子智能体。

## 什么时候出现

有东西可看时才出现，满足下面任意一条：

- 会话里除了它自己的智能体，还有加载着的子智能体；
- 会话自己的智能体有后台任务还没结束。

其余时候什么也不显示。位置在 Harness 的任务列表下面、目标条上面。

## 不做什么

- 不能停止或打断智能体和后台任务，也不能给它们发消息。
- 不改变智能体的行为：不影响调度，不向会话写入任何内容，模型看不到它。
- 没有设置，不保存任何数据。

## 关闭

打开「插件」，在「已安装」里找到「智能体监控」，关掉开关。

## 已知限制

- **每 2 秒刷新一次。** 页面每 2 秒向 Host 问一次，页面不可见时不问。显示最多滞后 2 秒，持续时间也是每次刷新才更新；很短的工具调用可能看不到。
- **只列出加载着的智能体。** 子智能体做完任务被 Harness 卸载后，就从列表里消失。
- **只显示正在执行的工具调用。** 模型在思考或输出文字时显示「思考中」，不显示内容。工具调用只显示最能说明它的一个参数（例如 `bash` 的命令），最多 80 个字符；同时执行多个时只显示最新的一个。
- **显示不下的内容看不全。** 名称、任务说明和工具调用过长时用省略号截断，没有办法展开。
- **持续时间依赖两边时钟一致。** 起点是 Host 记录的时间，终点是浏览器的时间；浏览器和 Host 不在同一台机器、时钟不一致时会有偏差。
- **文案只有中文和英文**，其他语言显示英文。
- **在 0.2.2-rc.3 发布版上能看到的更少。** 那个版本在子智能体停下后立刻卸载它，并取消它启动的后台任务，所以子智能体不会显示为「等待后台工作」，只看得到运行中的。那个版本的目标也不等会话自己的后台任务，所以目标那一行只在还有子智能体运行时出现。
- **进行中的工具调用、持续时间和任务说明读自会话日志**，用的是 Harness 已标记为不再推荐的同步读取接口，每次只读日志末尾有限的一段。Harness 以后不再把完整日志留在内存时，这三项会显示不出来，其余照常。

## 测试

```sh
npm test
```

不需要安装依赖。

- `test/host.test.mjs`：Host 端。用假的智能体、会话日志、后台任务和目标，覆盖成员和顺序、每种状态、正在执行的工具调用（以及它登记的任务不重复列出）、名称和任务说明的来源、缺少可选服务或某个智能体读不出来时的结果，以及目标等待的每个条件。
- `test/client.test.mjs`：浏览器端。覆盖注册位置、轮询（立即问一次、每 2 秒一次、页面不可见时不问、失败后保留上次结果）、摘要和持续时间的写法。渲染部分在 jsdom 里用 `deepseek-harness` 源码检出里的 React 驱动：本插件的某一级上级目录旁边要有一份装好依赖的 `deepseek-harness`（放在仓库旁边即可，在 worktree 里也能找到），或用 `HARNESS_DIR` 指定；找不到时跳过渲染部分。

```sh
npm run test:e2e
```

`test/e2e/run.mjs` 用临时 `DSH_HOME` 启动真实的 Harness（`web` profile），装上本插件和一个按脚本回答的模型。默认用已安装的桌面端运行时，也可以用 `DSH_APP` 指定应用包，或用 `DSH_CLI` 指定 `dsh` 可执行文件。脚本里的会话带一个目标，委派两个子智能体：一个启动不会结束的后台命令后停下，一个在前台执行命令。检查像浏览器一样登录后请求 Host 端的路由，核对每一行的状态、任务说明、进行中的工具调用、后台任务和目标等待；前台命令不能被列为后台任务。Harness 会不会保留子智能体由脚本自行判断：会保留时，启动后台命令的子智能体应显示为等待后台工作并列出该任务；不保留时（例如 0.2.2-rc.3）它不在列表里。浏览器端不在这项检查的范围内。

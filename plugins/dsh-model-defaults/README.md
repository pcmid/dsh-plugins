# @pcmid/dsh-model-defaults

在“模型”设置页的供应商列表上方增加“新会话”这一组配置，选中后立即保存。

| 配置 | 控件 | 保存位置 |
|---|---|---|
| 模型 | 模型和推理强度下拉框 | `agent-default-model` |
| 智能体 | 下拉框 | `agent-preset-registry.selectedDefault` |
| 权限 | 分段控件，选项来自 Harness 的权限目录 | `permission.defaultPreset` |
| 团队协作 | 开关 | 本插件的 `model-defaults.agentTeams` |

模型、智能体、权限都是 Harness 已有的配置，和“通用”“智能体”设置页写的是同一份，所以任何一处改了，其他地方都会同步。团队协作是本插件自己的配置，见下文。

- **完全权限需要确认。** 选它会弹出和 Harness 相同的风险确认，勾选后才能启用。
- **切换默认智能体或团队协作时**，当前打开的空白新会话会一起切换，和 Harness 自己的智能体设置页一致。
- **开发者工具关闭时**，PTC 和 Minimal 两个内置智能体不显示，也和 Harness 一致。

## 团队协作

打开后，新会话一创建就开启智能体团队协作，效果和在会话输入框的“模型与推理等级”菜单里打开 **启用智能体团队协作** 一样。

- **只影响新会话。** 新建的根会话和普通分叉会开启。恢复的旧会话保持各自保存的选择。子智能体跟随根会话，不单独设置。
- **会话里仍可单独关闭。** 这里只决定新会话的初始状态。
- **切换不会重新加载任何插件。** 开关是本插件可即时修改的配置（`agentTeams`），保存在 profile 的用户补丁层。Host 在每次创建会话时读取它，所以保存后下一个新会话就按新值创建。
- **为什么不改 Harness 的 `defaultEnabled`。** agent-team 自带的 `defaultEnabled` 只在插件启动时读取一次，改它会让 agent-team 重新加载，所以本插件在会话创建时直接调用 `agentTeams.setEnabled`，也就是输入框开关用的同一个接口。
- **Host 没有加载 agent-team 时不显示这个开关。**
- **开启失败不会阻止会话。** 如果新会话没能开启团队协作，Host 记一条警告，这个会话保持关闭，照常打开。

也可以直接改 profile 的 `cordis.patch.yml`：

```yaml
- id: model-defaults
  config:
    agentTeams: true
```

## 行为说明

- **输入框切换模型只影响当前会话，不会改默认模型。** 新会话始终使用这里设置的模型。Harness 原本会把输入框的选择写成默认模型，本插件拦截了这一步。还没有默认模型时例外：第一次选择仍会保存，否则新会话没有模型可用。
- **列表里已不存在的模型**会显示为“（不可用）”，配置保持不变，直到你另选一个。
- **搜索用哪个模型**由 `@pcmid/dsh-web-search-native` 在网页搜索设置里按供应商分别配置，不在这里。

## 已知限制

- **拦截的是 Harness 的内部方法。** Harness 没有提供关闭“输入框写默认值”的扩展点，所以本插件替换了 `agentDefaultModel.saveSelection`，卸载时还原。如果以后 Harness 改了这个方法名，插件会记一条警告，输入框又会开始改默认模型。卸载本插件也会恢复原有行为。
- **没发送的空白草稿会保留它自己的模型选择。** 在空白新会话里切换了模型但没有发送，这个草稿还是你选的模型；下一个新会话才回到默认模型。
- **和 Harness 的 `defaultEnabled` 互不影响。** 如果 profile 里另外打开了 agent-team 的 `defaultEnabled`，关掉这里的开关不会关掉它，新会话仍会开启团队协作。
- **页面位置靠 CSS 实现。** 模型页只提供列表下方的 `settings.models.footer` 插槽，所以这些配置用 CSS `order` 排到列表上方。如果以后页面布局变了，它们会退回页面底部，功能不受影响。
- **键盘 Tab 顺序和视觉顺序不一致。** DOM 里这些配置仍在列表之后。要彻底解决，需要 Harness 在列表上方增加一个插槽。
- **依赖 Chromium 的 Popover 和 CSS 锚点定位**，Harness 自带的菜单也依赖后者。
- **文案只有中文和英文**，其他语言显示英文；智能体和权限的选项名称沿用 Harness 自带的多语言文案。
- **没有提供给 agent 的工具。** 这些配置只能在设置页或配置文件里修改。

## 测试

`npm test` 运行离线测试：Host 部分的默认模型拦截和团队协作开启逻辑，以及前端团队协作开关的显示、保存和空白会话同步。测试从 `SCHEMASTERY_ENTRY` 解析 `@deepseek-ai/schemastery`；没有设置时，依次找本目录或仓库旁边的 `deepseek-harness` 源码检出，再找 `npm install` 装的 devDependency。

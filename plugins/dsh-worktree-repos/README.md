# @pcmid/dsh-worktree-repos

Harness 的「新建工作树」选项只在会话目录本身是 Git 仓库时出现。工作区是一个放着多个仓库的文件夹时（例如 `~/Projects` 下有好几个仓库），新会话没法从其中某个仓库切出 worktree。这个插件让这种工作区的新会话可以先选一个仓库，再用 Harness 自带的 worktree 选项选分支、切出 worktree。

依赖 Harness 的 forge 实验插件（`@deepseek-ai/dsh-experimental-forge-bundle`）提供的 worktree 选项。

## 用法

1. 在一个本身不是 Git 仓库、但子目录里有 Git 仓库的工作区新建会话。新会话那一行的右侧会出现仓库选择器，起初显示「选择仓库」。
2. 点开后是一个可搜索的列表：每行是一个仓库和它当前所在的分支，最后一行是「留在工作区根目录」。输入文字可筛选，↑↓ 选择，回车确认，Esc 关闭。
3. 选一个仓库，会话的工作目录就切到这个仓库。右侧紧接着出现 Harness 自带的分支和「新建工作树」勾选框，读起来是一条路径：`仓库 / 分支`。勾上并选好基准分支，发出第一条消息时就在这个仓库里切出 worktree。
4. 选「留在工作区根目录」，会话回到工作区目录。

## 设置

在「插件」页打开本插件，可以设置 **扫描深度**：在工作区下往里找几层目录，默认 1，只找工作区的直接子目录。改完保存即生效，不用重启。

- 带 `.git` 的目录算作仓库（`.git` 是目录或文件都算，所以 worktree 的检出目录也算）。
- 以 `.` 开头的目录跳过。
- 找到仓库后不再进入它的子目录。
- 符号链接只在指向仓库时算数，不会顺着链接往下找。
- 深度大于 1 时，列表里显示相对工作区的路径，例如 `dsh/deepseek-harness`。

也可以直接编辑 profile 的补丁：

```yaml
- id: worktree-repos
  name: '@pcmid/dsh-worktree-repos'
  config:
    depth: 2
```

## 行为说明

- **只在工作区本身不是 Git 仓库时出现。** 工作区目录或它的任何上级目录有 `.git`，就不显示选择器；扫描不到仓库时也不显示。
- **只在开始前能选。** 会话发出第一条消息后选择器消失，和 Harness 的 worktree 选项一样。
- **每次点开都会重新扫描**，刚克隆的仓库也会出现。
- **选了仓库就会切换目录，不论是否勾选工作树。** 没勾选时，会话就直接在这个仓库里工作。
- **换仓库会撤销已勾选的工作树。** 已勾选的工作树的基准分支属于原来的仓库，所以换仓库或回到根目录时会先撤销它，并提示「换了仓库，之前勾选的工作树已取消」，换好后需要重新勾选。

## 已知限制

- **判断是不是 Git 仓库靠找 `.git`。** 和 Git 自己的判断在 `GIT_DIR`、`GIT_CEILING_DIRECTORIES` 等环境变量下可能不同。
- **扫描深度设得很大、工作区又很大时，打开列表会变慢。** 每层都要读目录。
- **目录切换会告诉模型。** 选仓库时 Harness 会在第一条消息前附上「工作目录已从……改为……」的提示，切出 worktree 时还会再附一条。
- **设置表单用了 Harness 的组件库**（和 `@pcmid/dsh-todo-guard` 一样）。Harness 改了这些组件时，插件页的表单可能显示不出来，选择器不受影响。
- **文案只有中文和英文**，其他语言显示英文。
- **没有提供给 agent 的工具。**

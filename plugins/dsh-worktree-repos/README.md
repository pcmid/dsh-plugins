# @pcmid/dsh-worktree-repos

Harness 的「worktree」选项只在会话目录本身是 Git 仓库时出现。工作区是一个放着多个仓库的文件夹时（例如 `~/Projects` 下有好几个仓库），新会话没法从其中某个仓库切出 worktree。这个插件让这种工作区的新会话可以先选一个仓库，再用 Harness 自带的 worktree 选项选分支、切出 worktree。

依赖 Harness 的 forge 实验插件（`@deepseek-ai/dsh-experimental-forge-bundle`）提供的 worktree 选项。

## 用法

1. 在侧边栏的工作区标题上右键，或点它的「…」按钮，选 **扫描 Git 仓库**。再点一次（这时显示为 **取消扫描 Git 仓库**）关闭。工作区本身就在 Git 仓库里时，菜单里没有这一项。
2. 在这个工作区新建会话。新会话那一行的右侧多出一个仓库选择器，起初显示「选择仓库」。点开后列出工作区第一层子目录里的 Git 仓库。
3. 选一个仓库，会话的工作目录就切到这个仓库。随后右侧出现 Harness 自带的分支和「worktree」勾选框：勾上、选基准分支，发出第一条消息时就在这个仓库里切出 worktree。
4. 选「不选仓库」，会话回到工作区目录。

## 行为说明

- **只扫第一层子目录。** 带 `.git` 的子目录算作仓库（`.git` 是目录或文件都算，所以子模块和 worktree 的检出目录也算），以 `.` 开头的目录跳过。指向别处的符号链接按链接目标算。每次点开选择器都会重新扫描。
- **只在开始前能选。** 会话发出第一条消息后选择器消失，和 Harness 的 worktree 选项一样。
- **选了仓库就会切换目录，不论是否勾 worktree。** 没勾 worktree 时，会话就直接在这个仓库里工作。
- **换仓库会撤销已勾的 worktree。** 已勾的 worktree 的基准分支属于原来的仓库，所以换仓库或选「不选仓库」时会先撤销它，并提示「换了仓库，之前勾选的 worktree 已取消」，换好后需要重新勾选。
- **取消扫描后仍能切回。** 已经切进某个仓库的新会话，取消扫描后选择器还在，选「不选仓库」回到工作区目录后才消失。
- **配置按工作区目录保存**，写在 profile 的用户补丁层里本插件那一行的 `workspaces` 下。删除工作区不会清掉这一项，之后在同一目录重新添加工作区会继续生效。也可以直接编辑：

  ```yaml
  - id: worktree-repos
    name: '@pcmid/dsh-worktree-repos'
    config:
      workspaces:
        - /Users/me/Projects
  ```

## 已知限制

- **判断是不是 Git 仓库靠找 `.git`。** 工作区目录或它的任何上级目录有 `.git`，就当作在 Git 仓库里。和 Git 自己的判断在 `GIT_DIR`、`GIT_CEILING_DIRECTORIES` 等环境变量下可能不同。
- **目录切换会告诉模型。** 选仓库时 Harness 会在第一条消息前附上「工作目录已从……改为……」的提示，切出 worktree 时还会再附一条。
- **文案只有中文和英文**，其他语言显示英文。
- **没有提供给 agent 的工具。** 只能在工作区菜单和新会话那一行里操作，或手动编辑 profile 补丁。

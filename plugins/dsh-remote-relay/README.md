# @pcmid/dsh-remote-relay

通过自建的 [OpenChamber relay](https://github.com/openchamber/openchamber-relay)，在几台装了本插件的 DSH 之间切换，或从手机使用这台 DSH。relay 原样部署，不需要修改；它只看得到密文。DSH 的 Web GUI 继续只监听本机，不需要开放端口、配置 `trustedHosts` 或 TLS。

**已配对设备拥有你在被访问那台 DSH 上的全部权限**，包括执行命令和读写文件。只配对自己的设备，不用时在设置里移除。

## 组成

| 部分 | 位置 | 作用 |
|---|---|---|
| Host 插件 | `index.js` | 连接 relay，验证设备，把请求转发给本机 Web GUI |
| 设备切换（Host） | `remotes.js`、`loopback.js` | 本机作为设备连到其他 DSH，在本机回环地址上提供它们的界面 |
| 设置页和设备切换（Client） | `client.js` | 侧边栏底部的设备按钮；“设置 → 远程访问”：开关、relay 列表、配对链接、设备列表 |
| 手机启动页 | `launcher/` | 静态网页，部署到任意 HTTPS 站点；手机扫码或粘贴配对链接后在里面打开 DSH |

## 使用

1. 部署 relay（Cloudflare Workers、Docker 或 Node，见 relay 仓库的 README），得到 `wss://relay.example.com/ws`。
2. 在要被访问的 DSH 上打开“设置 → 远程访问”，开启远程访问，添加 relay 地址。状态变为“在线”后点“生成配对链接”。

### 多个 relay

relay 地址是一个有顺序的列表，顺序就是优先级，可以在设置页里添加、上下移动和删除（最多 8 个）。DSH 同时连着列表里的每个 relay，设置页逐个显示它们的状态和本机到它的延迟（HTTP `/health` 往返）；任意一个在线，远程访问就算在线。

- 配对链接带上全部 relay，按优先级排列。旧版本的启动页和插件只认第一个。
- 设备连接时先试第一个 relay，1.5 秒内没连上或者连接失败，就同时试下一个，依此类推，先完成握手的那个胜出，其余放弃。这和 OpenChamber 在直连、隧道、relay 之间挑选连接的方式一样。
- 连上以后一直使用这个 relay，直到断线才按优先级重新挑选；排在前面的 relay 恢复了，也不会自动切回去。
- 每次握手时 DSH 把当前的 relay 列表发给设备，设备保存下来，所以增删 relay 后已配对的设备不需要重新配对。只要设备记得的 relay 里还有一个能用，它就能连上来拿到新列表。
- 设备菜单里，已连接的设备显示它经过哪个 relay。在设备的“⋯”菜单里选“线路与延迟…”，会测量经过每个 relay 到对方 DSH 的往返时间：正在使用的连接直接测，其他 relay 各开一条临时连接测完就关。这里只测量，不切换连接。手机启动页只能测当前打开的 DSH。

### 从另一台 DSH 切换过去

两台都装本插件。被访问的那台不需要部署启动页。

1. 复制被访问那台生成的配对链接（`dsh-remote://pair#…`；配置了启动页时是启动页链接，同样可用）。
2. 在要发起访问的 DSH 上，点侧边栏底部“设置”上方的设备按钮，选“添加设备…”，粘贴链接，点“添加并切换”。
3. 之后用同一个按钮在“本机”和已添加的设备之间切换。远程那台的界面里同一位置也有这个按钮，用来切回本机或切到别的设备。在菜单里右键已添加的设备，或点它右侧的“⋯”（手机上一直显示，电脑上悬停时显示），选“移除设备”即可移除，确认后本机会通过隧道让对方同时把本机从它的设备列表里删掉，对方离线时会提示这一步没有完成。重新添加同一台设备时沿用本机原来的设备密钥，对方的列表里不会出现重复的条目。

切换时本机界面保持不动，直到对方的界面加载好才整窗切过去；连接失败不会离开本机，按钮和菜单里会显示原因（离线、被对方移除）和对应操作。已经打开过的设备在本次窗口里保持连接，再次切换是即时的。每台设备有一个由它的身份密钥决定的颜色，在所有 DSH 上都相同。

### 手机

1. 把 `launcher/` 目录部署到一个 HTTPS 静态站点，例如 Cloudflare Pages、GitHub Pages，或在 Docker 部署的 Caddy 里加一个 `file_server`。**这个源只放启动页**：同源的其他脚本可以使用浏览器里保存的设备密钥。升级插件后重新部署整个目录；`index.html` 用 `app.js?v=<版本>` 加载脚本，所以 CDN 只要不长时间缓存 `index.html`，其他文件缓存多久都不会新旧混用。
2. 在设置页填写手机启动页地址，生成配对链接后会显示二维码。
3. 用相机扫描二维码，在启动页里点“配对”。之后打开启动页会自动连接上次的 DSH；iOS 可以“添加到主屏幕”。

也可以先打开启动页，在“添加 DSH”里粘贴配对链接，或点“扫描二维码”用启动页自己打开摄像头扫码。iOS 上添加到主屏幕的启动页和 Safari 不共享已配对的设备，在主屏幕版本里配对时用这种方式。浏览器有原生二维码识别（`BarcodeDetector`，如 Android 上的 Chrome）时直接使用；否则（如 Safari）按需加载 `launcher/vendor/jsQR.js`（[jsQR](https://github.com/cozmo/jsQR) 1.4.0，Apache-2.0，许可证见同目录的 `jsQR.LICENSE`）。

在手机上打开 DSH 后，侧边栏（窄屏下点左上角展开）底部“设置”上方同样有设备按钮，显示当前的 DSH。它的菜单列出这个浏览器配对过的所有 DSH，点一台即可切换；手机不是 DSH，菜单里没有“本机”，“添加设备…”回到启动页的“添加 DSH”；点菜单里某台 DSH 右侧的“⋯”选“移除设备”，会把它从这个浏览器移除，启动页首页也能移除。启动页（包括主屏幕 App 的状态栏）的颜色跟随当前 DSH 实际使用的主题，而不是手机的深浅色设置；回到启动页首页后再跟随手机。DSH 页面要等它的界面应用了页面启动时的主题后才淡入显示：DSH 的界面会先按手机的深浅色显示，等设置里的主题经隧道传过来才切换，在慢的网络上就是一次明显的黑白闪烁。页面顶部的状态条从打开 DSH 起一直显示（“正在连接…”“正在加载…”），直到 DSH 页面显示出来，这期间随时可以点“离开”；之后只在连接断开、重连失败或被移除时出现，恢复连接后显示 2 秒“已连接”再消失；手机唤醒时这类 2 秒内就恢复的断线不会显示。DSH 上装的是旧版本插件、页面里没有设备按钮时，顶部保留一个小圆点，点开后可以离开。

配对链接只能用一次，默认 10 分钟内有效（`pairingMinutes`）。

### 上次打开的会话

装了本插件的 DSH 记得最后在哪个窗口打开了哪个会话：电脑上的 DSH、手机启动页里的 DSH、从另一台 DSH 切换过来的界面，都算。任何一个窗口重新打开时都进这个会话；它已被删除或归档时，就在最近的工作区开一个新会话。手机启动页会在 DSH 页面加载前就告诉它要打开哪个会话，并等这个会话显示出来才把页面淡入，所以不会先闪一下新会话。DSH 自己也会在每个浏览器里记住上次的会话，本插件只是把「上次」变成所有窗口共用的。

## 配置

都在设置页里修改，保存到本插件行 `remote-relay` 的配置中，修改后立即生效，不需要重启。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 是否保持与 relay 的连接，让配对过的设备访问本机 |
| `relays` | `[]` | relay 的 WebSocket 地址列表，按优先级排列；只写域名时补全为 `wss://<域名>/ws` |
| `relayUrl` | 空 | 旧版本的单个 relay 地址；`relays` 为空时才使用，设置页保存列表时会清空它 |
| `launcherUrl` | 空 | 手机启动页地址；为空时没有二维码，配对链接用 `dsh-remote://pair#…` 形式 |
| `hostName` | 计算机名 | 其他设备上显示的名称，也是本机配对到其他 DSH 时的默认设备名 |
| `pairingMinutes` | `10` | 配对链接有效分钟数 |

从本机切换到其他设备不需要开启 `enabled`，用的是配对链接里带的、之后由对方更新的 relay 列表。

本插件在 DSH 凭据存储里保存四条记录：
- `remote-relay/identity`：本机身份密钥。删除后会换一个新的 `serverId`，所有设备都要重新配对。
- `remote-relay/devices`：可以访问本机的设备。
- `remote-relay/remotes`：本机能切换到的设备，内容包括本机在对方那里的设备密钥、每台设备的 relay 列表（`relayUrls`，`relayUrl` 保留为第一个，供旧版本读取）、回环地址标签，以及回环端口。
- `remote-relay/last-session`：所有窗口最后打开的会话。

## 工作方式

```
另一台 DSH / 手机启动页 ─wss─► relay（只转发）◄─wss─ DSH Host 插件 ─► 127.0.0.1 上的 Web GUI
```

- **relay 协议**：插件实现 openchamber-relay v1 的 host 端，在列表里的每个 relay 上各保持一条 `host-control` 连接。DSH 用一把 ECDSA P-256 密钥签名 `host-control` 和每个 `host-data` 连接；`serverId` 是公钥的 SHA-256。relay 每个 `serverId` 最多 16 个并发设备、每分钟 60 次新连接，所以每台设备的所有 HTTP 请求和 WebSocket 都复用同一条连接。
- **端到端加密**：设备发送临时 ECDH 公钥和设备公钥；DSH 回复自己的临时公钥、身份公钥和对握手记录的签名，设备检查身份公钥的哈希等于 `serverId`，因此 relay 无法冒充 DSH。双方用 HKDF 派生每个方向各一把 AES-256-GCM 密钥，配对时再混入一次性配对密钥；设备在第一帧里用设备私钥签名握手记录。帧按方向计数，丢失、重放或乱序的帧会导致连接关闭。
- **转发**：被访问的 DSH 用自己的浏览器 cookie 登录本机 Web GUI，再把设备的请求和 WebSocket 原样转发过去；cookie 不会发给设备，设备送来的 cookie、Origin 和 `Sec-Fetch-*` 头会被丢弃。
- **设备切换**：发起访问的 DSH 在 Host 进程里为每台已添加的设备保持一条隧道，并在回环端口上以 `http://<随机标签>.localhost:<端口>/` 提供它的界面。标签有 130 位随机数，是唯一的准入凭据：只有 Host 头是已知标签加本端口的请求才会进入隧道，带了其他 Origin 的请求、跨站的非导航请求都会被拒绝。每台设备的界面因此是独立的源，和本机 DSH、和其他设备都不共享 cookie 和存储。本机界面把它放进一个铺满窗口的 iframe（不允许导航顶层窗口）；两边的插件用 `postMessage` 交换设备列表、当前状态和窗口属性（macOS 桌面版的标题栏布局），菜单由当前显示的那台按自己的主题渲染。粘贴配对链接的对话框始终由本机渲染，远程页面看不到链接。没有请求和 WebSocket 的隧道 2 分钟后关闭。
- **手机启动页**：Service Worker 把 iframe 里 DSH 页面的请求交给启动页窗口，经隧道转发；页面最前面注入一段脚本，把 DSH 的 `__DSH_TRANSPORT__.createWebSocket` 指向隧道，所以 `/api/remote.mux` 也走隧道。文件上传同样不经过 Service Worker：脚本还提供 DSH 的上传载体 `__DSH_FILE_UPLOAD__`，在页面里读出文件内容后直接经隧道发送（DSH 默认从 Blob Worker 上传，经 Service Worker 转发后在 iOS 上会失败）。gzip 响应在浏览器里解压。启动页用和设备切换相同的 `postMessage` 协议回应 DSH 页面里的插件，把本浏览器配对过的 DSH 作为设备列表发给它，所以手机上的设备按钮和菜单由 DSH 自己渲染。

## 开发

```sh
# 先在本地启动两个 relay：git clone openchamber-relay && npm install && PORT=18788 npm start，另开一个 PORT=18789
RELAY_URL=ws://127.0.0.1:18788/ws RELAY_URL_2=ws://127.0.0.1:18789/ws npm test
RELAY_URL=ws://127.0.0.1:18788/ws node --import ./test/hooks.mjs test/launcher.e2e.mjs   # 需要 Chrome 和 playwright-core
```

测试使用 DSH 源码检出中的 schemastery（见 `test/hooks.mjs`），以及 relay 依赖里的 `ws` 包（`WS_MODULE`）。

## 已知限制

- 远程设备是 owner 身份，没有只读或受限模式。需要把会话分享给别人时，请使用 DSH 的 Liveshare。
- 设备切换依赖浏览器把 `*.localhost` 解析到本机。桌面版（Electron）、Chrome、Edge 和 Firefox 可以；Safari 不保证，在 Safari 里打开 DSH 时可能无法显示其他设备。
- 在 macOS 桌面版里显示其他设备时，窗口顶部能否拖动取决于 Electron 是否认可 iframe 内的拖动区域，尚未在桌面版上验证。
- 显示其他设备时，粘贴配对链接的对话框使用本机的主题，可能和当前显示的设备主题不同。
- 远程那台没有装本插件（或版本较旧）时，它的界面里没有设备按钮；本机会在左下角显示一个浮动按钮用来切回。
- 手机启动页依赖 Service Worker；无痕模式或禁用 Service Worker 的浏览器无法使用。DSH 的 HMR 事件流在 Service Worker 被系统回收后会重连。
- 被访问的 DSH 的 Web GUI 使用自签名 TLS 证书时，WebSocket 转发不可用（HTTP 转发可用）。
- relay 协议版本由 OpenChamber 维护；请固定 relay 的版本。relay 使用 FSL-1.1-ALv2 许可：可以自建自用，不能拿它对外提供商业中转服务。
